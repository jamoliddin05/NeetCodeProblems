Two stacks that grow and shrink together

The second stack has one row for every row of the first. Row k of it holds the smallest value in rows 0 to k of the first stack. Step through the calls below and watch both change at the top only.

    Arrow keys work too. Click a call to jump to it.

      Why one number is not enough

      The first idea is to keep one variable min and update it on every push. Push works. Pop breaks it. Try it:

      • push(3): min becomes 3.
      • push(1): 1 is smaller, so min becomes 1.
      • pop(): removes 1. The stack is now just 3, so the minimum should be 3.
      • But min still says 1. When it changed from 3 to 1, the 3 was written over. Nothing remembers it.

      To get 3 back you would have to look through the whole stack again. With n elements that is n steps, which breaks the O(1) rule. (O(1) means each call does the same small amount of work no matter how big the stack is. O(n) means the work can grow with the number of elements.)

      The fix: never write over an old minimum. Keep every one of them, in the order they were made. That list of minimums is the second stack. To watch the variable go wrong, choose "Popping the minimum" in the Calls menu above, "One min variable" in the Compare menu, and press Next until the first pop().

      Is the second one a stack or a list?

      In Python it is a list. Both of them are. "Stack" is not a different type here. It describes how the list is used: you add only at the end with append, and you remove only from the end with pop(). Your solution can use two ordinary Python lists.

      So the real question is: why touch the second list only at its end? Take the stack 3, 1, 2:

      • pop() always removes the newest value. Here that is 2, in row 2.
      • The minimum written when 2 was pushed is also the newest minimum: row 2 of the min stack, the last 1. So it is at the end of the second list too.
      • Remove it. The min stack is now 3, 1. Its end is 1, and the smallest of 3 and 1 is 1. Correct, with no searching.
      • Rows 0 and 1 of the min stack did not need to change. Row 0 describes only row 0 of the main stack. Row 1 describes only rows 0 and 1. Those rows are still there and still hold 3 and 1.

      Row k of the min stack depends only on rows 0 to k of the main stack. Those rows cannot change while row k exists, because the main stack changes only at its top. So a minimum written at push time stays correct until its own row is popped.

      That is why the second list must change in the same places as the first: add at the end when the first adds at the end, remove from the end when the first removes from the end. Then both lists always have the same length, and row k of one belongs to row k of the other.

      What about a sorted list of the values?

      Another idea for the second list: keep all the values sorted, so the smallest is always first. getMin() would be easy. The trouble is push and pop. Take the stack 3, 1, 2 again. The sorted list is 1, 2, 3.

      • pop() removes 2, the newest value. In the sorted list 2 is in the middle. You have to find it, remove it, and shift 3 one place left.
      • push(0) puts 0 at the front of the sorted list. Every other value shifts one place right.

      With n values a single push or pop can move n values: O(n). The answers are right, but each call does more and more work as the stack grows. To count the moves, choose "Smaller and smaller" in the Calls menu and "A sorted list" in the Compare menu. Every push lands at the front.

      The reason it goes wrong: the stack removes the newest value, and a sorted list keeps values by size, not by age. The newest value can be anywhere in it. A heap has the same problem. (A heap is a list kept only partly sorted, so that the smallest value is always first. In Python that is the heapq module. Adding a value or removing the smallest one costs O(log n), much less than shifting a sorted list.) For the stack 3, 1, 2 the heap could be 1, 3, 2. Removing the smallest value is easy, but pop() asks it to remove the newest one, 2. To find 2 in the heap you would have to search for it. Only a list ordered by age, newest at the end, puts the value pop() removes in a place you can reach in one step. A list ordered by age and used only at its end is exactly a stack.

      The min stack uses one extra slot per element, so n extra slots for n elements: O(n) space, which is what the problem allows.
